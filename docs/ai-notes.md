# Где ИИ ошибся и что исправлено

Проект сделан с Claude Code. Здесь собраны ошибки агента из журнала этой работы: что было не так, кто или что это заметил и что изменили. Правила, которые закрывают эти ошибки, записаны в [CLAUDE.md](../CLAUDE.md).

Кто замечал:
- **самопроверка** — агент перечитал свой код до запуска;
- **хук** — проверка команд до запуска;
- **скриншот** — снимок отрисованного дашборда;
- **рецензент** — один из четырёх независимых агентов. Перед публикацией в два прохода они пытались сломать числа, воспроизводимость и тексты, у каждого был свой контекст.

Главный вывод: формулы и SQL почти не ошибались. Независимый пересчёт из CSV совпал с SQL с первого прогона. Ошибки сидели в выводах и в проверках. Агент, который писал код, свои ошибки в выводах не видел, их поймали только рецензенты. Поэтому рецензия отдельными агентами — обязательный шаг, а не опция.

## Расчёты и выводы

| Что ИИ сделал не так | Кто заметил | Что исправлено |
|---|---|---|
| «Возвраты из списанных добавляют к NPL 0,61 п.п.» — это доля их суммы в портфеле, без учёта знаменателя. Рядом стоял расчёт «без них NPL 9,51%», то есть на самом деле разница 0,50 п.п. Комитет, вычтя 0,61 из 10,01, получил бы не то число | Рецензенты, двое из трёх | Факт считается как разница долей с возвратами и без них: 0,50 п.п. Правило в CLAUDE.md |
| «Излечения» из 90+ подкреплялись доводом: остаток у них снизился на 2,7%, меньше, чем у кредитов без просрочки (3,8%), значит, просрочку не погасили. Довод не держится. Порядок зависит от взвешивания: в среднем на кредит у «излеченных» снижение даже больше. А у кредитов, оставшихся в 90+, остаток упал даже сильнее, чем у кредитов без просрочки (4,0% против 3,8%): в этих данных показатель группы не различает | Рецензенты | Довод убран вместе с фактами, на которых он стоял. Вывод «подтвердить платежи» остался, теперь он опирается на то, что просрочка больше 90 дней обнулилась за месяц |
| После этого вывод перечислял только два объяснения обнуления просрочки, погашение или ошибку выгрузки, и пропускал реструктуризацию без отметки, хотя соседний вывод о ней говорит | Рецензент второго прохода | Три объяснения, в действии — проверить и изменения графика |
| Риск «пролонгаций без отметки о реструктуризации» считался по 379 кредитам с истёкшим сроком, хотя 17 из них уже реструктуризированы и уже в NPL | Рецензенты | База — 362 кредита на 81,7 млрд ₸, отдельный факт во вьюхе и в независимом пересчёте |
| Вьюха фактов для выводов брала группу заёмщика только из топ-10 и соединялась через `CROSS JOIN`. Если бы группа оказалась вне топ-10, пустой CTE молча обнулил бы **все** факты, и README остался бы без чисел без единой ошибки | Самопроверка | Агрегат по всем группам, который всегда даёт одну строку; `LATERAL` для `VALUES`; проверка «все факты посчитаны» |

## Тексты против кода

| Что ИИ сделал не так | Кто заметил | Что исправлено |
|---|---|---|
| README, CLAUDE.md и дашборд обещали, что непрошедшая проверка «останавливает сборку», а `scripts/build.sh` проверки не запускал: битые данные дошли бы до выгрузки | Рецензенты | `build.sh` сверяет CSV с SHA256 и запускает `sql/90_checks.sql` до выгрузки |
| README обещал, что каждая проверка сначала проверена на испорченных данных, а порчей покрыты 10 SQL-проверок из 46 | Рецензент второго прохода | Формулировка по факту: 20 видов порчи, каждую ловит свой контроль |
| CLAUDE.md утверждал, что все правила в функциях, а пороги PAR30 и PAR90 были записаны прямо в выражениях вьюх, и синтетические тесты их не проверяли | Рецензент | Функции `is_par30`, `is_par90`, `dpd_bucket`; во всех 13 синтетических случаях теперь сверяются и PAR, и корзина |
| После этого в фактах для выводов остались ставки провизий, вписанные числами (`0.50 - 0.01`) мимо функции: изменись правило, выводы остались бы старыми | Рецензент второго прохода | Сценарные ставки берутся из `provision_rate()` |
| Инструкция для Docker запускала сборку сразу после `docker run`, когда сервер ещё делает initdb и не слушает TCP. А на Linux файлы от `docker exec` создавались бы от root | Рецензенты | Ожидание `pg_isready`, сборка и проверки с хоста. Сам вариант не запускался: Docker на машине нет. Вместо него всё прогнано на PostgreSQL 16.15 и 17.11 |

## Проверки

| Что ИИ сделал не так | Кто заметил | Что исправлено |
|---|---|---|
| Тест идемпотентности считал объекты в отпечатке по шаблону `^psql:.*WARNING`, а psql при чтении из heredoc печатает просто `WARNING:`. Счётчик дал 0, и сравнение двух пустых отпечатков прошло бы как «идемпотентно» | Сработала заложенная заранее защита «объектов меньше 15 — отпечаток не работает» | Шаблон исправлен |
| После исправления тест всё равно опирался на слово `WARNING:`, которое сервер с русскими сообщениями пишет как «ПРЕДУПРЕЖДЕНИЕ:». Так же тест порчи заголовка CSV искал текст ошибки | Рецензент | Своя метка `fp|` в выводе и код SQLSTATE `22P04` вместо текста |
| Проверки «остаток > 0» и «курс > 0» были написаны как `x ~ regex AND x::numeric <= 0` в расчёте на короткое замыкание. PostgreSQL порядок вычисления в `WHERE` не гарантирует, и приведение могло упасть на битом значении раньше regex | Самопроверка | Приведение внутри `CASE` |
| Проверку «курс есть на каждую дату» сначала написал через типизированную вьюху курсов. При битой дате в `fx.csv` она упала бы с ошибкой приведения типа раньше, чем гейт сырья покажет причину | Самопроверка | Проверка читает `raw.fx` напрямую |
| В psql-скрипте проверок `\if` получал число (а принимает только boolean), а для остановки стояло `SELECT 1/0` | Самопроверка | Boolean-выражение и `RAISE EXCEPTION` с понятным текстом |
| Для проверки настроек сервера запросил `SHOW lc_collate`. Такого параметра в PostgreSQL 16+ нет: память модели смешала версии, а проект обязан работать на `postgres:16` | Ошибка psql | Синтаксис сверяется с 16-й версией, сборка прогнана на настоящей PostgreSQL 16.15 |

## Окружение и дашборд

| Что ИИ сделал не так | Кто заметил | Что исправлено |
|---|---|---|
| Запустил локальный PostgreSQL без `LC_ALL` при русской локали терминала; на macOS postmaster упал при старте | Лог сервера | `LC_ALL=C` в `scripts/pg_local.sh` |
| В скрипт кластера вписал запасной системный путь к `pg_ctl`, которого на машине нет | Хук | Бинарники из `PATH` или из `PG_BIN` |
| Плитки ключевых метрик на `facet`: подписи фасетов не отключились ни `header: null`, ни `labels: false` (Vega кладёт их в заголовок ячейки), над плитками появились дубли | Скриншот; в коде спеки ошибки не видно | Плитки на одном слое с пиксельными координатами (`scale: null`) |
| Подписи на мосте портфеля и в матрице миграции наезжали на оси и обрезались; строка изменения вылезала за рамку плитки; переключатель метрики оказался под графиком, потому что CSS искал класс vega-embed не на том элементе | Скриншот, рецензент | Отступы шкал, матрица на всю ширину, плитки на всю сетку, исправленный селектор |

## Что из этого следует для работы с ИИ

- Выводы и формулировки проверять отдельным агентом, которому дан код и данные, а не мой вывод. Автор не видит свою ошибку в рассуждении.
- Каждую проверку сначала заставить упасть на заведомо плохих данных (`scripts/test_controls.sh`, 20 случаев).
- Итоговые числа подтверждать вторым расчётом, который писался без доступа к первому.
- График принимать по картинке, а не по коду.
